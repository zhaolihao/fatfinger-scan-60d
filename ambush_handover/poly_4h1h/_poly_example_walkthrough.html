4h×1h 嵌套策略：执行机制真实例子还原

数据：Polymarket BTC Up/Down 30 天真实成交（9/10–10/9，180 对） · 每侧 5 美元 · 价差 1% · 2026-10-10

① 一句话比喻：赛马场的两个投注窗口

同一场赛马，场边开了两个投注窗口：一个赌「整场 4 小时 BTC 涨不涨」，一个赌「最后一小时涨不涨」。

你专挑这样一个瞬间：两个窗口的「冷门方向刚好相反」——比如大窗口（4h）冷门是「涨」，小窗口（1h）冷门是「跌」。然后两边各押 5 块钱冷门票。

押完之后，只要任意一边突然变热（价格翻倍），你就把那一边全部卖掉，把 10 块本金收回来。剩下那一边就成了白送的彩票——到期中了是纯赚，没中也不亏（本金已收回）。

④ 这套判断在代码里长什么样

把上面的"人话"翻译成机器的判断条件（已简化，去掉了性能细节）：

# 每个 1h 成交时刻，检查一次能不能入场
if 4h便宜侧 == "up"  and 1h便宜侧 == "dn":   # 方向必须相反
    pass
elif 4h便宜侧 == "dn" and 1h便宜侧 == "up":
    pass
else:
    continue          # 方向相同 → 跳过

if 4h价格 >= 0.20 or 1h价格 >= 0.20:        # 两侧都必须够便宜（<阈值）
    continue

# 入场：两边各买 5 美元
4h份数 = 5.0 / (4h价格 × 1.01)   # 1.01 = 1% 价差
1h份数 = 5.0 / (1h价格 × 1.01)

# 出场：从入场那一刻往前扫描每一笔价格
if 份数 × 当前价 >= 10.0:        # 市值翻倍（收回全部本金）
    卖出价 = 当前价 × 0.99      # 再扣 1% 价差
    全卖，这一侧结束

# 到期还没卖的：按真实结果结算
if 这一侧 == 真实赢家: 每一份付 $1
else:                 每一份付 $0

关键点：完全没有用"未来信息"——每一步只用当时已经成交过的价格，买入和卖出的判断都只看到当下。

⚠️ ⑤ 讲解过程中自查发现的重大建模错误（必须纠正）

错在哪：「持有到到期结算」这一步，旧回测用的是到期前最后一个市场价格当卖出价，而 Polymarket 二元市场的真实结算是 赢了 $1/份、输了 $0/份。

为什么后果严重：买价越便宜，买的份数越多。像例子里 $0.001 买了 4950 份，输掉时旧模型却按 $0.001 结算，等于把 $4.95 本金退回来了——但真实世界里输了就是 $0。

佐证：180 个已收盘 4h 市场里，有 50 个最后价格不在 0 或 1 附近（33 个在 0.01–0.1，12 个还在 0.1–0.9 的中间态），说明"最后价"根本不能代表结算结果。

⑥ 结论：修正后还剩下什么

  • 正期望仍在，但强度大幅下降。主推 THR=0.20：ROI +22.8%，胜率 61/80（76%），但 t 值只有 +1.87 —— 已经不到统计显著线（2.0）。之前说的"t=3.93 显著"是被结算 bug 抬上去的。
  • 越激进越先崩。THR=0.05 修正后直接转负（−4.5%）。因为阈值越小越依赖"极低价格买彩票"，而结算修正正好把"买错了还能退回本金"的幻觉打掉。
  • 策略骨架是对的：靠"任一腿翻倍就收回本金"把下行砍掉，另一腿零成本博高赔率——这个结构在真实结算下依然盈利，只是没之前那么夸张。
  • 还有一个没算进来的风险：极端价（如 $0.001）会买到近 5000 份，真要卖出时盘口深度未必吃得下，1% 价差假设偏乐观。实盘小资金试才知真实滑点。

建议下一步

  • 不要按之前"显著"的结论加大投入，按修正后的 +22.8% ROI / t=1.87 重新评估。
  • 先用小资金（200–500 美元）实盘跑 1–2 周，重点验证：① 真实滑点是不是 1% 以内；② 极端价单子能不能真成交。
  • 同时补 ETH + 另一段行情（大跌/横盘）做二次稳健性确认，看 t 值能不能回到 2 以上。
