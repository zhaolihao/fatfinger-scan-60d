## 0. 一句话结论

在父周期（4h）与子周期（1h）**同一时刻**、**两侧便宜侧方向相反**、**两边价格都 < 阈值**时各买 1 美元；
任一侧市值 ≥ 总成本即全卖收回本金（动态保本），另一侧持有到到期按 **$1/$0** 二元结算。

**现行推荐：只用第 4 小时（最后一小时）+ THR=0.20 + 每侧 1 USD**
→ ROI **+22.77%**、t=**+1.88**、n=**80**、胜率 75%（60/80）、30 天总投入 $160、总盈亏 **+$36.5**。

⚠️ **t=+1.88 未达显著线 2.0**，样本仍是 30 天单一 BTC 行情段。结论是「正期望但不够硬」，不是「已验证稳定盈利」。

## 1. 市场结构（关键，理解错就全错）

Polymarket BTC Up/Down 有**两大家族**，结算规则完全不同：

| 家族 | slug 形态 | 例子 | 周期 | 结算依据 |
|---|---|---|---|---|
| 4h（父） | `btc-updown-4h-{unix}` | `btc-updown-4h-1789228800` | 4 小时 | Chainlink BTC/USD 区间 TWAP ≥ 起点 → Up |
| 1h（子） | `bitcoin-up-or-down-{month}-{day}-{year}-{time}-et` | `bitcoin-up-or-down-september-12-2026-3pm-et` | 1 小时 | Binance BTC/USDT 1h 蜡烛 close ≥ open → Up |

- **1h 家族 series slug = `btc-up-or-down-hourly`，recurrence = hourly**，已确认**可完整回溯 30 天**（180/180 个 4h 窗口都配到对应 1h 市场）。
- 时区：ET = UTC-4（10 月）。slug 用 ET 12 小时制（如 `11pm-et`）。
- **1h 市场 `orderMinSize = 5`，单位是「份」不是「美元」；`orderPriceMinTickSize = 0.01`。**
- 嵌套配对：4h 窗口 `12:00→16:00 ET` 的**最后一小时** = `15:00→16:00 ET` = slug `...-3pm-et`（注意是 3pm 不是 4pm）。

### 两个必须知道的坑（都已踩过并修正）

1. **结算模型**：持有到到期必须按 **赢了 $1/份、输了 $0/份** 结算，**禁止用到期前最后市场价代替**。
   早期版本（v3 及以前）用最后市场价，导致"买 $0.001 的票输了还能退回本金"的荒谬结果，把 ROI 从 +22.8% 虚抬到 +44.3%、t 虚抬到 +3.93。
   已验证：180 个已收盘市场里有 **50 个**最后价格不在 0/1 附近（12 个还在 0.1–0.9 中间态），证明"最后价"根本代表不了结算。
2. **量纲重复缩放**：脚本曾把已按 MIN_SIZE 算好的均值又乘一次 MIN_SIZE，报出的金额虚高 5 倍（"+$1770" 实为 "+$182"）。

## 2. 策略规则（v5 现行版）

### 入场条件（每个 1h 成交时刻检查一次，首次满足即入场）
```
1. 4h 便宜侧 与 1h 便宜侧 方向必须相反（一个 Up 便宜、另一个 Down 便宜）
2. 两侧价格都 < THR（默认 0.20）
3. gap 过滤：|4h Up 价 − 0.5| ≥ GAP（默认 0.00，实测该过滤基本无效）
```

### 下单（CEO 修正：单位是「份」）
```
每侧下注 MIN_SIZE = 1.0 USD
份数 = 1.0 / (价格 × (1+SLIP))，SLIP = 1% 价差
若份数 < 5 份（orderMinSize）：默认按 5 份补齐（成本随之上升）
  → 也可设 strict=True 直接跳过该次入场
```
**关键发现**：THR=0.20 正好是"5 份门槛不吃人"的上限。THR=0.30 时 97 次入场被迫加仓，ROI 被砍到 +8.44%。

### 出场
```
从入场时刻往前扫每一笔成交价：
  任一侧 份数 × 当前价 ≥ 总成本  →  该侧全部卖出（再扣 1% 价差）
另一侧继续持有到到期：
  赢了 $1/份，输了 $0/份
```
**无未来信息**：所有判断只用当时已成交过的价格（tick 级真实成交路径）。

## 4. 如何运行

所有脚本用**脚本所在目录**作工作目录（`OD = dirname(abspath(__file__))`），把仓库整目录 pull 下来即可直接跑。

```bash
# Python 3.13（Windows 托管环境）
PY="C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe"

# ★ 主回测：只看第 4 小时（推荐配置）
HOURS=3 THR_LIST=0.30,0.25,0.20,0.15,0.10,0.05,0.02 \
SLIP=0.01 MIN_SIZE=1.0 MIN_SHARES=5.0 MODE=A \
OUT=_out_hour4.txt $PY -u _poly_4h1h_v5.py

# 全 4 小时对照（CEO 提出的第 2/3 小时是否该加）
HOURS=0,1,2,3 THR_LIST=0.20,0.15,0.10 SLIP=0.01 MIN_SIZE=1.0 MIN_SHARES=5.0 MODE=A \
OUT=_out_all.txt $PY -u _poly_4h1h_v5.py
```

**环境变量**：
| 变量 | 默认 | 说明 |
|---|---|---|
| `SLIP` | 0.01 | 买卖价差（1% = 实盘乐观，2% = 压力） |
| `MIN_SIZE` | 1.0 | 每侧下注 USD |
| `MIN_SHARES` | 5.0 | 交易所最小份数（orderMinSize） |
| `MODE` | A | A=每个 4h 窗口只入最早一次；B=每个满足条件的小时各入一次 |
| `HOURS` | 0,1,2,3 | 参与配对的小时序号（0=第1小时 … 3=第4小时/最后一小时） |
| `THR_LIST` | 0.30…0.02 | 扫描的价格阈值列表 |
| `GAP` | 0.00 | 参考价间距过滤（实测无效） |
| `OUT` | — | 输出文件名 |

**重新抓数据**（需代理，Clash 默认 `127.0.0.1:7897`；注意脚本里硬编码了代理端口）：

## 5. 已得结论（按时间线，含自我修正）

### ① 周期越长越有效（7 天样本）
- 4h×1h：ROI +34.5%（价差1%），t=+1.98，n=24
- 15m×5m（同 7 天、2017 对大样本）：ROI **−2.2%**，t=−0.61，**无正期望**
- → 分钟级嵌套无效，小时级以上才有效

### ② 扩样到 30 天（42 对 → 180 对）
- 样本 4.3 倍，t 从 1.7~2.3 升到 2.3~3.9（当时以为显著）
- 最优阈值从 0.30 移到 0.20

### ③ 结算模型修正（重大）
| THR | 旧结算 ROI/t | 真实二元结算 ROI/t |
|---|---|---|
| 0.30 | +27.5% / +3.38 | +14.2% / +1.64 |
| **0.20** | +44.3% / +3.93 | **+22.8% / +1.87** |
| 0.10 | +42.1% / +2.45 | +3.6% / +0.20 |
| 0.05 | +36.4% / +2.48 | **−4.5% / −0.29（转负）** |

→ 正期望仍在，但**不再统计显著**（t 1.87 < 2.0）。越激进的阈值越先崩。

### ④ CEO 修正「5 元 → 5 份」，每侧改 1 美元
| THR | 每局实际成本 | 被 5 份门槛强制加仓次数 | ROI |
|---|---|---|---|
| 0.30 | $2.47 | 97 | +8.44% |
| 0.25 | $2.17 | 79 | +7.03% |
| **0.20** | **$2.01** | 41 | **+22.77%** |
| ≤0.15 | $2.00 | 0 | +13.86% |

### ⑤ CEO 要求加第 2/3 小时 → **反直觉：加了反而更差**
先用 `HOURS=3` 复现 v4（+22.77 vs +22.79、+13.86 vs +13.86、−4.53 vs −4.53，逐位吻合）确认代码无 bug，差异确实来自"早入场"。

**逐小时拆解（THR=0.20）：**
| 小时 | 触发次数 | ROI | t | 4h腿均价 | 保本触发率 |
|---|---|---|---|---|---|
| 第1小时 | **0** | — | — | — | — |
| 第2小时 | 12 | +4.67% | +0.22 | 0.140 | 75.0% |
| **第3小时** | 25 | **−34.10%** | **−2.69** | 0.128 | **56.0%** |
| **第4小时** | 61 | **+23.71%** | +1.69 | 0.056 | 75.4% |

THR=0.15 更极端：第 3 小时 **−69.14% / t=−5.10 / 保本率仅 28.6%**。

**机制（关键指标 = 保本触发率）**：
越接近 4h 收盘，冷门侧价格越极端（第4小时均价 **0.056** vs 第3小时 0.128）。价格越低 → 1 美元买到的份数越多 → **价格只要动一点点就翻倍**，保本容易触发。
早入场价格没那么极端，翻倍需要的真实反转幅度大得多，"收回本金"很少发生 → 两条腿双双归零。

**机会成本**：一旦在第 2/3 小时入场就不再等第 4 小时，全 4 小时模式下第 4 小时只剩 61 次（原本 80 次），**19 次最好的机会被挤掉**。

**总对照（THR=0.20）**：全 4 小时 +6.63% / t=+0.67　vs　只看第 4 小时 **+22.77% / t=+1.88**
→ **现行决策：不加第 2/3 小时，只用最后一小时。**

### ⑥ GAP「参考价间距」过滤：实测无效
GAP 从 0 加到 0.35，ROI 几乎不变（高 GAP 反而 n 略降）。当前 gap 定义 = `|4h Up价 − 0.5|`，衡量的不是想要的"两市场参考价间距"。
**真正防双输的是出场规则（翻倍保本），不是入口过滤。**

## 7. 方法论约束（必须遵守）

- **禁止 look-ahead bias**：所有买卖判断只用当时已成交过的价格，不用未来信息。
- **tick/秒级真实成交数据**，不用分钟 K 线聚合。
- **二元市场持有到到期 = $1/$0 结算**，禁止用最后市场价近似。
- 交付前必须做「真实例子逐步还原」自检（这一步直接发现了结算 bug）。
- 输出的美元金额必须手工复核量纲，警惕重复缩放。
